# HeroesCompanion v2 — переписывание с нуля

Status: ready-for-agent

## Problem Statement

Текущее приложение (v1, ветка `legacy/v1-reference`) — компаньон для настольной игры «Герои», покрывающий 12 фракций двух коробок. Код накопил баги (краш при неизвестной фракции, хрупкий матчинг модификаторов через `startsWith`, «Наги»-хардкод в расчёте силы, «порядок действий» с 5 нумерованными позициями вместо 4 из 5, дублирование состояния, дед-код), стили хардкодятся в каждом экране, тестов нет. Игра вышла на третью коробку (6 новых фракций), приложение их не поддерживает. Пользователи накопили записи игр, которые нельзя терять при обновлении.

## Solution

Переписать приложение с нуля (v2) как базу: тот же фиче-сет, что у v1, но на все 18 фракций (3 коробки × 6), с исправленными багами, чистой архитектурой (Riverpod + go_router), данными фракций в JSON-ассетах, единой темой без хардкода цветов и сохранённым форматом записей игр с миграцией из v1 при первом запуске. Приложение остаётся компаньоном (ADR-0001): сопровождает партию, не проверяет правила.

## User Stories

1. Как игрок, я хочу выбрать фракцию для партии из всех 18 фракций, сгруппированных по 3 частям игры, чтобы играть любой коробкой.
2. Как игрок коробки 3, я хочу найти в приложении 6 новых фракций (Гриболюды, Оборотни, Архонты, Ящеры, Тёмные эльфы, Циклопы) с их юнитами и силой, чтобы играть третьей коробкой.
3. Как игрок, я хочу видеть юнитов своей фракции с их базовой силой, чтобы знать свою армию.
4. Как игрок, я хочу вести счёт юнитов каждого типа (общее число), чтобы знать размер армии.
5. Как игрок, я хочу отмечать юнитов, заявленных в бой, чтобы количество «в бой» не превышало общего числа.
6. Как игрок, я хочу видеть силу армии (всего) и силу в бой, чтобы сравнивать с соперниками.
7. Как игрок фракции «Наги», я хочу видеть силу краков по правилу n², чтобы расчёт соответствовал игре.
8. Как игрок, я хочу вести счёт ресурсов (дерево, железо, золото и фракционные — ярость, краки и т.д.) колёсиками-счётчиками, чтобы знать свой склад.
9. Как игрок, я хочу видеть текущий раунд партии (1–16) и переходить к следующему, чтобы знать стадию партии.
10. Как игрок, я хочу после 16-го раунда завершить партию и перейти к подсчёту очков.
11. Как игрок, я хочу выстроить порядок действий (4 действия из 5 с уровнями 1–4), как выбрал первый игрок, чтобы действия выполнялись в правильной очерёдности.
12. Как игрок, я хочу применять модификаторы силы к юнитам (переключатели и счётчики), чтобы улучшения отражались в силе армии.
13. Как игрок фракции «Элементали», я хочу включать улучшения «Майи» по цепочке 7→10→14 без срабатывания «чужого» модификатора, чтобы расчёт был точным.
14. Как игрок, я хочу, чтобы состояние модификаторов партии не рассинхронизировалось при повторном открытии модального окна, чтобы введённые улучшения не пропадали.
15. Как игрок, я хочу после партии ввести очки по 6 ячейкам подсчёта (здания, фундаменты, ресурсы, победы в сражениях, артефакты, сумма) для 1–4 игроков, чтобы определить победителя.
16. Как игрок, я хочу видеть автоматическую сумму очков каждой категории, чтобы не считать вручную.
17. Как игрок, я хочу указать имя и фракцию каждого игрока (до 4), чтобы запись была полной.
18. Как игрок, я хочу сохранить результаты партии, чтобы они появились в истории.
19. Как игрок, я хочу просматривать историю игр, отсортированную по дате, чтобы следить за прогрессом.
20. Как игрок, я хочу очистить историю с подтверждением, чтобы удалить старые записи.
21. Как пользователь v1, я хочу, чтобы мои записи игр автоматически перенеслись в v2 при первом запуске, чтобы ничего не потерялось.
22. Как игрок, я хочу видеть версию приложения на главном экране, чтобы знать сборку.
23. Как игрок, я хочу видеть фон и цвета своей фракции на экране партии, чтобы приложение соответствовало игре.
24. Как игрок, я хочу открывать окно поддержки проекта (донат), чтобы поддержать автора.
25. Как игрок, я хочу выйти из экрана партии двойным нажатием «назад», чтобы случайно не потерять партию.
26. Как игрок, я хочу вернуться в главное меню из истории, чтобы продолжить навигацию.

## Implementation Decisions

- **Архитектура**: Riverpod (состояние партии — провайдер сессии), go_router (типизированная навигация). Платформенно-нейтральный код, цель — Android.
- **Доменный слой**: чистый Dart без импортов Flutter-виджетов. Модели: `Faction`, `Unit` (имя, базовая сила, модификаторы), `StrengthModifier` двух типов — `Toggle` (включён → бонусная сила) и `Counter` (базовая + счёт × шаг), с явной привязкой к юниту (поле `unit`, без матчинга по подстроке). Сессия партии: раунд (1–16), ресурсы, армия (всего/в бой), порядок действий (4 из 5 с уровнями 1–4), состояния модификаторов — единый источник истины.
- **Сила армии**: Σ(количество × сила юнита с учётом модификаторов); для фракции «Наги» — краки по n² (закодировано в данных фракции как признак, не строкой-хардкодом).
- **Данные фракций**: JSON в ассетах (18 фракций, группировка по частям игры; у фракции: имя, цвет, путь фона, ресурсы, юниты с силой и модификаторами). Источники: коробки 1–2 — данные v1 со сверкой по `docs/rules/`, коробка 3 — чтение планшетов с изображений PDF агентом + вычитка пользователем.
- **Навигация по меню**: выбор фракции — 3 секции по частям игры.
- **Хранилище**: `shared_preferences`, ключ `score_records`, формат v1 без изменений (`{dateTime, playerScores: [{playerName, score, faction}]}`), ADR-0002.
- **Миграция**: при первом запуске v2 (тот же applicationId `com.example.heroescompanion`, что у v1) — чтение старых записей, преобразование в новую модель, отметка о завершённой миграции; повторно не запускается.
- **UI**: русскоязычный, единая тема Material 3 (цвет фракции — из данных), без хардкода стилей; экран ввода очков переработан (крупные поля, читабельная сетка); экран партии — в духе v1 (фон фракции, колёсики-счётчики, армия, модификаторы, порядок действий).
- **Исправления багов v1**: отсутствие краша при неизвестной фракции; «порядок действий» — 4 действия с уровнями 1–4 (пятое пустое); выход с экрана партии — двойное нажатие «назад»; отсутствие дед-кода.
- **Инструменты**: `flutter_lints`, `package_info_plus` (версия на главном меню).

## Testing Decisions

- **Единый шов тестирования — доменный слой**: чистый Dart, тесты `flutter test` без виджетов. Хороший тест проверяет внешнее поведение (вход → выход), не детали реализации.
- Покрывается: парсинг и валидация JSON фракций (все 18, цепочки модификаторов привязаны к своим юнитам); сила армии (включая Наги n²); модификаторы (toggle, counter, цепочки «Майя»); сериализация/десериализация записей (round-trip формата v1); миграция записей v1 (пусто, частично битые, полные).
- UI проверяется вручную на устройстве (сборка у пользователя).

## Out of Scope

- Отслеживание карты, перемещения, чудовищ, крепостей, артефактов, зданий, фундаментов (возможные будущие тикеты, ADR-0001).
- Особые механики правил за пределами модели toggle/counter (ярость-апгрейды орков, мехозавр +1/3 науки и т.п.).
- Мультиплеер/синхронизация между устройствами; интернационализация; виджет-тесты.
- Ассеты (изображения) — пользователь готовит сам; в коде только пути, как в v1.

## Further Notes

- Референс поведения: ветка `legacy/v1-reference`, правила — `docs/rules/rules1-3.pdf`.
- У v1 нет папки `android/` в репо; проект v2 создаётся заново с `--org com.example` для совпадения applicationId.
- Записи v1: ключ `score_records`, список JSON-строк.
- Донат-модалка и отображение версии переносятся из v1 как часть базы.
