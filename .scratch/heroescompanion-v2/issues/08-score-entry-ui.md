## Comments

Реализовано в `lib/features/scores/presentation/score_entry_screen.dart` (экран «Ввод очков»: игрок 1 с фракцией из партии — подпись «Фракция: …», игроки 2–4 — имя + дропдаун фракций из каталога; 6 ячеек на игрока — 5 полей ввода (здания, фундаменты, ресурсы, победы в сражениях, артефакты) + автосумма, пересчёт по вводу; «Сохранить результаты» — собирает только заполненных игроков (непустое имя), без имён — подсказка без записи; заголовок «Ввод очков» — термин «результат игры» в глоссарии _Avoid_). Хранилище — `lib/features/scores/data/game_record_storage.dart` (GameRecordStorage + интерфейс StringListPreferences, инжектируется для чистого Dart) и `game_record_providers.dart` (адаптер над SharedPreferences, провайдер gameRecordStorageProvider): пишет в ключ `score_records` список JSON-строк формата v1 (ADR-0002), `loadAll` читает как v1 с пропуском битых — публичный API для тестов и тикета 09. После сохранения — SnackBar «Результаты успешно сохранены» и `pushReplacement` на `/score_history` (назад не возвращает к вводу; в v1 был обычный push). Названия по глоссарию: `GameRecordStorage`, не `ScoreRecord*` (CONTEXT.md: _Avoid_: score record). Тесты: `test/features/scores/data/game_record_storage_test.dart` (7 тестов: формат v1 байт-в-байт, дополнение без затирания, round-trip, порядок, битые строки — проверены прогоном в изолированном чистом Dart-пакете, анализ чист) и `test/features/scores/score_entry_screen_test.dart` (6 виджет-тестов: рендер 4 игроков и 6 ячеек, автосумма, запись одного игрока + переход к истории, только заполненные, выбор фракции из дропдауна, подсказка без имён; проверка записанного — через публичный `loadAll()`, переход — по типу ScoreHistoryScreen — требуют финального прогона `flutter test` на машине со SDK). Общий фейк хранилища — `test/helpers/fake_string_list_preferences.dart`. Обновлён `test/features/game/game_screen_test.dart` (ожидание заглушки → «Ввод очков» + «Фракция: Тестовая»).
