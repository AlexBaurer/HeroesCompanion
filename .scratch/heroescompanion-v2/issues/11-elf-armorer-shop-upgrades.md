# 11 — Система апгрейда войск эльфов: здание «Лавка бронника»

**What to build:** Механика здания «Лавка бронника» фракции Эльфы (rules1.pdf, с. 19): перед сражением игрок платит любое количество дерева и модифицирует силу **боевых единиц на то количество дерева, которое потратил** (заявленных «в бой») на текущее сражение. Эффект временный — сила на планшете не зачёркивается, в следующем сражении платится снова. Значения из примера правил: Энт 6→10, Грифон 3→5, Пикси 1→2. Модификация — не наём.

Строится как обобщённый механизм (признак в данных фракции, как `armyPower` из тикета 03), данные — только у эльфов:

- **Данные (JSON, `elfs.json`):** секция `battleUpgrade` — цена (Любое количество дерева), целевые силы по юнитам (`pixi` → 2, `grifon` → 5, `ent` → 10). Валидатор тикета 02 расширяется: цена-ресурс из ресурсов фракции, лимит ≥ 1, целевые силы только у существующих юнитов.
- **Домен (сессия тикета 03):** состояние активации эффекта (оплачена цена) и выбранных юнитов (≤ лимита, только из заявленных «в бой»). Сила юнита в бою = целевая сила апгрейда для выбранных, иначе обычная сила с модификаторами; `deployedArmyStrength` учитывает апгрейды, `totalArmyStrength` — нет. Сброс выбора при `advanceRound()` (граница сражения).
- **UI (экран партии тикета 07):** у эльфов в модалке модификаторов силы секция «Лавка бронника»: кнопка «Применить эффект» (списывает выбранное количество дерева), выбор модифицированных юнитов из «в бой», живой пересчёт силы в бою.

## Comments

Реализовано по правилам (rules1.pdf, с. 19): «Лена платит 2 дерева и может модифицировать силу двух боевых единиц... сила энта модифицируется до 10... действует только на время текущего сражения».

- **Данные**: `assets/factions/elfs.json` — секция `battleUpgrade` (`resource: "Дерево"`, `limit: 2`, `powers: {pixi: 2, grifon: 5, ent: 10}` — из примера правил). Валидатор (`FactionParser._readBattleUpgrade`): цена-ресурс из ресурсов фракции, лимит ≥ 1, целевые силы ≥ 0 только у существующих юнитов (обобщено сообщение `FactionUnknownUnitException`), неизвестные поля отклоняются. `Faction.battleUpgrade: BattleUpgrade?` — признак как `armyPower`, есть только у эльфов (контракт-тест данных).
- **Домен** (`GameSession`): `applyBattleUpgrade(wood, unitIds)` — списывает дерево (при повторном применении — разницу с оплаченным: добирает/возвращает), выбор ≤ `limit`, только из «в бой», юниты без целевой силы/дубликаты/нехватка дерева → `ArgumentError`, фракция без здания → `StateError`. `unitBattlePower` = целевая сила для выбранных, иначе обычная с модификаторами (апгрейд перекрывает toggle); `deployedArmyStrength` учитывает апгрейды, `totalArmyStrength` — нет. `advanceRound()` сбрасывает оплату и выбор без возврата дерева (граница сражения); `setArmyDeployed(…, 0)` убирает юнит из выбора.
- **UI**: `BattleUpgradeSection` в модалке модификаторов (`StrengthModifiersSheet`): степпер количества дерева, чекбоксы юнитов «в бой» (вне боя и при заполненном лимите — недоступны), «Применить эффект», статус оплаты и живой пересчёт «Сила в бой». Локальное состояние инициализируется из сессии — повторное открытие модалки не теряет применённый эффект (пользовательская история 14). Секция показывается только фракциям с `battleUpgrade`.
- **Тесты**: парсер — 8 (разбор, отсутствие поля, ресурс, лимит, неизвестный юнит, пустые/строковые силы, неизвестное поле); сессия — 13 (сила без эффекта, списание и выбор, целевые силы, 22-пример, вне «в бой», лимит, дубликат, нехватка дерева, повторное применение, сброс раундом, вывод из боя, toggle-перекрытие, StateError/ArgumentError); данные — 2 контракт-теста эльфов; виджеты — 3 (отсутствие секции без здания, применение+живой пересчёт+сброс раундом, недоступность вне боя и лимит). Проверено прогоном в изолированном чистом Dart-пакете (анализ чист, 35/35 проверок), требуют финального прогона `flutter test` на машине со SDK.

Механика отсутствовала в v1 (эльфы там без модификаторов) и в спеке числилась в Out of Scope («особые механики за пределами модели toggle/counter») — вводится как осознанный отдельный тикет по ADR-0001. Модель toggle/counter не подходит: апгрейд приравнивает силу к фиксированному значению, временен и ограничен сражением, поэтому отдельный признак в данных фракции и состояние в сессии.
